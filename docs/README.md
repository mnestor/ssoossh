# ssoossh documentation

**ssoossh** (pronounced *sue-sssh*) is SSO for SSH: users authenticate via OIDC
and receive short-lived SSH certificates instead of managing long-lived keys.
Self-hosted, homelab-friendly, early development.

## Release plan

**[release-plan.md](release-plan.md) is the current plan.** It supersedes the
delivery plan for everything still open, and scopes the first release to user
certificates plus PAM. Each phase has its own file:

1. [Repo hygiene and release-blocking debts](release-phase1-hygiene.md)
2. [End-to-end harness, the merge gate](release-phase2-e2e.md)
3. [PAM build environment](release-phase3-pam-build-env.md)
4. [PAM certificate type, server side](release-phase4-pam-server.md)
5. [PAM module and the four checks, client side](release-phase5-pam-client.md)
6. [Release artifacts and the tag](release-phase6-artifacts.md)
7. [Deployment stack, documentation, rehearsal](release-phase7-deploy-docs.md)

The project's original delivery plan (phases 1 to 10, covering everything
from the initial build to GA) has been retired now that
[release-plan.md](release-plan.md) exists. Phases 1 to 5 of it were done —
they record how the working login loop got built — and phases 6 to 10 are
superseded, split between the release plan above and the release-2 items
listed there. The old phase files are gone; what mattered from them was
carried into the release plan's decisions and corrections tables.
