What is installed

/usr/local/bin/ssoossh
/usr/local/share/man/man1/ssoossh.1 and one page per subcommand
/usr/local/share/man/man5/ssoossh.yaml.5
/usr/local/share/ssoossh/ssoossh.yaml   the annotated defaults
/usr/local/share/doc/ssoossh-client/    LICENSE, NOTICE, THIRD-PARTY-LICENSES.md

/usr/local/bin is on the default PATH and /usr/local/share/man is on the default manpath, so ssoossh version and man ssoossh both work in a new shell with nothing else to set up.

Configuration

None is required: the defaults are compiled into the binary, and --server is enough to try it. The file installed at /usr/local/share/ssoossh/ssoossh.yaml is a copy to start from, not one the client reads. Put your edits in one of the places it does read, last of these wins:

/etc/ssoossh/ssoossh.yaml     machine-wide, and the only file `enforce` is read from
~/.config/ssoossh.yaml        yours
./ssoossh.yaml                the working directory
--config <file>
sudo mkdir -p /etc/ssoossh
sudo cp /usr/local/share/ssoossh/ssoossh.yaml /etc/ssoossh/ssoossh.yaml

Nothing under /etc is written by this installer, so an upgrade never touches a file you edited. man ssoossh.yaml describes every key.

Using it

ssoossh --server https://ssh.example.com ssh login

That opens a browser, and on approval writes a certificate into your SSH agent. ssoossh ssh config prints the two lines for ~/.ssh/config that make it happen automatically on first connection to a host. ssoossh ssh inspect shows what you are currently holding.

Removing it

sudo rm -rf /usr/local/bin/ssoossh \
    /usr/local/share/ssoossh \
    /usr/local/share/doc/ssoossh-client \
    /usr/local/share/man/man1/ssoossh*.1 \
    /usr/local/share/man/man5/ssoossh.yaml.5
sudo pkgutil --forget @IDENTIFIER@

pkgutil --files @IDENTIFIER@ lists exactly what the receipt claims before you delete anything.
